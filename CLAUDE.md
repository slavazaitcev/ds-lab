# ds-lab: правила для Claude

Лаборатория дизайн-системы. Токены приходят из Figma, компоненты пишутся в коде, из компонентов собираются прототипы экранов. Автор и владелец системы: Слава (дизайнер). Общаемся по-русски, имена в коде на английском, комментарии короткие и по-русски.

## Стек и команды

React 19 + TypeScript + Vite, Storybook 10, обычный CSS (без Tailwind и CSS-in-JS).

- `npm run storybook` — каталог компонентов на http://localhost:6006
- `npm run dev` — песочница на Vite
- `npm run tokens` — пересобрать CSS-переменные из `tokens/*.json`
- `npm run typecheck` и `npm run build-storybook` — проверка перед коммитом

## Токены: источник правды

- `tokens/*.json` — экспорт из Figma (DTCG): `primitives`, `light`, `dark`, `numbers`. Их заменяет только человек новым экспортом.
- `src/styles/tokens.css` и `src/styles/tokens.generated.ts` генерируются скриптом `scripts/build-tokens.mjs`. Руками не править.
- Тема light по умолчанию, dark включается `data-theme="dark"` на `<html>`. Любой компонент проверяем в обеих темах.
- `src/styles/pending-tokens.css` — временные отступы, шрифты, скругления и размеры контролов. Это предположения, не данные из Figma. Когда в Figma появятся настоящие токены, их переносят в `tokens/`, а файл удаляется.

## Правила для компонентов и экранов

1. Цвета только из семантических токенов: `var(--color-bg-…)`, `var(--color-text-…)`, `var(--color-border-…)`, `var(--color-icon-…)`.
2. Запрещено: hex, rgb, hsl и именованные цвета в `src/components` и `src/screens`; переменные `--primitive-*` (они только для семантики); новые «серые» и любые цвета, которых нет в токенах.
3. Disabled: `opacity: var(--opacity-disabled)`. Своих значений прозрачности не придумывать.
4. Размеры, отступы, шрифты и скругления: только переменные из `pending-tokens.css`. Новые числовые значения в CSS компонента не вписывать, сначала добавить переменную туда.
5. Если нужного токена нет (цвет для состояния, отступ, размер), не выдумывать значение. Взять ближайший существующий токен, поставить в коде комментарий `/* TODO(token): … */` и добавить строку в `docs/token-gaps.md`. В ответе человеку сказать об этом прямо.
6. Состояния hover, active, focus-visible, disabled, loading описываем всегда, где они применимы. Токены `hover`/`active` берём парами с `default` из той же группы.
7. Перед созданием нового компонента или заметным изменением существующего: сначала
   показать таблицу (откуда берутся значения, какие токены, что под вопросом) и
   дождаться подтверждения. Не создавать файлы сразу.

## Иконки

- Только Tabler (`@tabler/icons-react`, версия зафиксирована в package.json) и только через `src/icons`. Напрямую из `@tabler/icons-react` в компонентах и экранах не импортировать.
- `src/icons/index.ts` реэкспортирует только иконки, которые стоят в Figma-компонентах. Новая иконка попадает туда, когда появилась в Figma.
- Рисуем через обёртку `Icon` (`src/icons/Icon.tsx`): `icon`, `size` (s/m/l), `color`.
- Цвет иконки только токеном `color.icon.*` и задаётся явно. От цвета текста не наследуется, `currentColor` как источник цвета не используем. Внутри компонента цвет по состояниям ставим через `--ds-icon-color` (токеном) и `color="component"`.
- Размеры только через `--icon-size-*`. Толщина линии только по `src/icons/spec.ts` (там же формула пересчёта stroke).
- Для экранов и компонентов можно использовать только иконки из `src/icons/index.ts`.
- `StoryIcon` и страница Icons / All Tabler icons (`src/stories/tabler`) — только для экспериментов в Storybook. В `src/components` и `src/screens` их не импортировать (исключение: stories). Утверждённую иконку добавляем в `src/icons/index.ts`.
- Этот инструмент работает только в `npm run storybook`. В `npm run build-storybook` он выключен (см. `.storybook/main.ts`): иначе в сборку попадают все ~6200 иконок Tabler.

## Структура и именование

```
src/components/<Name>/   Name.tsx, Name.css, Name.stories.tsx, index.ts
src/icons/               Icon.tsx, spec.ts, index.ts (набор иконок из Figma)
src/screens/             экраны-референсы и новые экраны, собираются только из src/components
src/stories/             страницы документации (каталог токенов)
src/stories/tabler/      эксперименты с любыми иконками Tabler, только dev Storybook
```

- Компоненты в PascalCase, один компонент на папку, публичный экспорт через `index.ts`.
- CSS-классы с префиксом `ds-`: `.ds-button`, `.ds-button--primary`, `.ds-button__label`. Состояния для Storybook: `.is-hover`, `.is-active`, `.is-focus`.
- Стили вариантов задаём через локальные CSS-переменные (`--btn-bg` и т. п.), состояния описываем один раз.
- Для каждого компонента делаем stories: `Playground` (Controls), все варианты и размеры, все состояния рядом.
- Доступность: нативные элементы (`button`, `input`), видимый фокус, `aria-*` где нужно.

## Прототипы экранов

- Экран собирается из готовых компонентов. Нужного компонента нет: сначала сказать об этом и предложить сделать его, не рисовать «на месте» из div.
- Данные вымышленные: имена, номера телефонов, тарифы и организации придумываем. Реальных данных компании в репозитории быть не должно.
- Интерактив настоящий: фильтры фильтруют, модальные окна открываются, строки раскрываются.

## Составные компоненты

- Составной компонент собирается только из готовых компонентов слоем ниже, ничего не рисует заново. Слои: `Icon` → простые (Button, Input, Checkbox) → составные (Field, Select) → блоки (панель фильтров, форма, таблица). Импортировать можно только вниз по списку.
- Нужного компонента нет: сначала сказать об этом и предложить сделать его, не копировать чужие стили.
- Параметры называем так же, как у существующих компонентов (`variant`, `size`, `intent`, `disabled`, `loading`). Перед новым именем посмотри `Button`.
- Stories составного компонента показывают его состав и все состояния.

## Расхождения, скиллы и журнал

- Перед сверкой с Figma прочитай `docs/token-gaps.md`. Записанные там расхождения это решения человека, а не ошибки.
- Скиллы лежат в `.claude/skills/`. `/port-component [ссылка] [Имя]` переносит или обновляет компонент из Figma. `/audit-mockup [ссылка]` проверяет макет по правилам системы (только чтение). Правила проверки живут в самом скилле.
- Каждый опыт и вывод по нему записываем в `docs/experiment-log.md`.

## Перед коммитом

`npm run typecheck`, `npm run build-storybook`. Если менялись токены, сначала `npm run tokens` и коммитим сгенерированные файлы вместе с исходниками.

## Выбор модели и экономия лимита

Claude Code работает на одной модели за сессию и сам её не меняет по сложности.
Модель выбирает человек через `/model`. Задача Claude — в начале работы оценить
сложность и, если текущая модель заметно тяжелее или легче нужной, одной строкой
предложить переключиться (`/model haiku|sonnet|opus`) и продолжить. Это подсказка,
а не блокировка: если человек не переключил — работаем на текущей.

Ориентир по сложности:
- Haiku — механическое: переименовать, переформатировать, поправить один класс,
  добавить строку токена, ответить по файлу, запустить команду. Обычно `/effort low`.
- Sonnet — повседневное и дефолт: перенос компонента по готовой таблице, stories,
  реализация по понятному ТЗ, аудит макета.
- Opus — рассуждение: архитектура, новый составной компонент с нуля, разбор спорного
  расхождения токенов, роадмап, правка правил и скиллов, неочевидная отладка.
- Fable — редко: длинный многошаговый рефакторинг по многим файлам, долгий прогон.

Правила:
- По умолчанию Sonnet. Вниз до Haiku на мелочи, вверх до Opus только когда задача
  правда требует рассуждения.
- Не дёргать модель слишком часто: лишняя возня и ошибочно выбранная модель стоят
  дороже, чем просто Sonnet.
- Глубину на той же модели регулируем `/effort`, а не сменой модели.

## Спецификации дизайн-системы

В `specs/` лежат спецификации дизайн-системы разработчиков. Порядок чтения: spacing.md, colors.md, typography.md, затем файл нужного компонента в `specs/design-system/docs/components/`.

- Наши токены в `tokens/` остаются источником значений. Спецификации используем для сверки: варианты, размеры, состояния, поведение компонентов.
- Если значение или название в спецификации расходится с токенами, не выбирай сам: запиши в `docs/token-gaps.md` и покажи мне.
- Неизвестное помечай UNKNOWN, не угадывай.
