# ds-lab: правила для Claude

Лаборатория дизайн-системы. Токены приходят из Figma, компоненты пишутся в коде, из компонентов собираются прототипы экранов. Автор и владелец системы: Слава (дизайнер). Общаемся по-русски, имена в коде на английском, комментарии короткие и по-русски.

## Стек и команды

React 19 + TypeScript + Vite, Storybook 10, обычный CSS (без Tailwind и CSS-in-JS).

- `npm run storybook` — каталог компонентов на http://localhost:6006
- `npm run dev` — песочница на Vite
- `npm run tokens` — пересобрать CSS-переменные из `tokens/*.json`
- `npm run typecheck` и `npm run build-storybook` — проверка перед коммитом

## Токены: источник правды

- `tokens/*.json` — экспорт из Figma (DTCG): `primitives`, `light`, `dark`, `numbers`. Их заменяет только человек новым экспортом.
- `src/styles/tokens.css` и `src/styles/tokens.generated.ts` генерируются скриптом `scripts/build-tokens.mjs`. Руками не править.
- Тема light по умолчанию, dark включается `data-theme="dark"` на `<html>`. Любой компонент проверяем в обеих темах.
- `src/styles/pending-tokens.css` — временные отступы, шрифты, скругления и размеры контролов. Это предположения, не данные из Figma. Когда в Figma появятся настоящие токены, их переносят в `tokens/`, а файл удаляется.

## Правила для компонентов и экранов

1. Цвета только из семантических токенов: `var(--color-bg-…)`, `var(--color-text-…)`, `var(--color-border-…)`, `var(--color-icon-…)`.
2. Запрещено: hex, rgb, hsl и именованные цвета в `src/components` и `src/screens`; переменные `--primitive-*` (они только для семантики); новые «серые» и любые цвета, которых нет в токенах.
3. Disabled: `opacity: var(--opacity-disabled)`. Своих значений прозрачности не придумывать.
4. Размеры, отступы, шрифты и скругления: только переменные из `pending-tokens.css`. Новые числовые значения в CSS компонента не вписывать, сначала добавить переменную туда.
5. Если нужного токена нет (цвет для состояния, отступ, размер), не выдумывать значение. Взять ближайший существующий токен, поставить в коде комментарий `/* TODO(token): … */` и добавить строку в `docs/token-gaps.md`. В ответе человеку сказать об этом прямо.
6. Состояния hover, active, focus-visible, disabled, loading описываем всегда, где они применимы. Токены `hover`/`active` берём парами с `default` из той же группы.

## Структура и именование

```
src/components/<Name>/   Name.tsx, Name.css, Name.stories.tsx, index.ts
src/screens/             экраны-референсы и новые экраны, собираются только из src/components
src/stories/             страницы документации (каталог токенов)
```

- Компоненты в PascalCase, один компонент на папку, публичный экспорт через `index.ts`.
- CSS-классы с префиксом `ds-`: `.ds-button`, `.ds-button--primary`, `.ds-button__label`. Состояния для Storybook: `.is-hover`, `.is-active`, `.is-focus`.
- Стили вариантов задаём через локальные CSS-переменные (`--btn-bg` и т. п.), состояния описываем один раз.
- Для каждого компонента делаем stories: `Playground` (Controls), все варианты и размеры, все состояния рядом.
- Доступность: нативные элементы (`button`, `input`), видимый фокус, `aria-*` где нужно.

## Прототипы экранов

- Экран собирается из готовых компонентов. Нужного компонента нет: сначала сказать об этом и предложить сделать его, не рисовать «на месте» из div.
- Данные вымышленные: имена, номера телефонов, тарифы и организации придумываем. Реальных данных компании в репозитории быть не должно.
- Интерактив настоящий: фильтры фильтруют, модальные окна открываются, строки раскрываются.

## Перед коммитом

`npm run typecheck`, `npm run build-storybook`. Если менялись токены, сначала `npm run tokens` и коммитим сгенерированные файлы вместе с исходниками.
