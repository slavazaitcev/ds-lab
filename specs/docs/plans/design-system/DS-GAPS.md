# Пробелы и противоречия в `design-system/`

## Как работать с этим списком

1. Сначала прочитайте `AGENTS.md`, раздел «Как писать документацию в
   `design-system/`». Формат файлов менять нельзя.
2. Берите задачи по одной, по порядку номеров.
3. Источник правды — код `autumn-ui`. Figma — только для сверки.
4. Не придумывайте значения. Если значение не нашлось ни в коде, ни в Figma —
   оставьте `UNKNOWN` и допишите к задаче строку «Не найдено: где искали».
5. Каждое значение записывайте в таблицу нужного раздела: одна величина — одна
   ячейка; цвет — роль, Light, Dark; hex заглавными буквами.
6. После выполнения задачи отметьте её: замените `- [ ]` на `- [x]` и допишите,
   что записано и куда.
7. Все изменения одной сессии — в одном коммите с записью в
   `design-system/CHANGELOG.md` (см. `AGENTS.md`).

Типы задач:

| Тип | Что значит |
|---|---|
| пробел | значения нет в документации |
| противоречие | в разных местах записаны разные значения |
| проверить | значение записано, но вызывает сомнение |
