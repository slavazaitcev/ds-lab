# Модель «100 % UI/UX-покрытия» виджета

Шаблон для сессий: каждый блок — что проверить и что сдать в спеке. Каждый пункт
закрывается фактом с источником (`[код]` — файл:строка autumn-ui, `[Figma]` —
узел, `[вывод]` — из других фактов) либо уходит в `_work/design-system/discrepancies.md`
с ID, статусом `open` и планом уточнения. «Молчаливых» дыр не остаётся.

Конечная форма спеки: факты (число + источник), `UNKNOWN` только с записью в
discrepancies, «Критерии соответствия» покрывают все блоки ниже.

## A. Анатомия и метрики

- Все части виджета, сверху вниз / снаружи внутрь; у каждой части: размеры,
  отступы, зазоры, радиусы, типографика (кегль/межстрочный/вес).
- Таблица метрик по ступеням `sm` / `m` / `lg` (и исключения), если шкала есть.
- Хром: фон, бордер (толщина/цвет), тень, скругление, курсор.
- Где «нет своей типографики» — сказано явно («наследует из окружения»).

## B. Варианты и виды

- Каждый `variant` / вид / режим, меняющий вид или поведение, описан **отдельно**
  (не списком имён): чем отличается вид, чем поведение.
- Вид по умолчанию назван; значения по умолчанию каждого пропа — с числом.
- Композиты: какие части из каких виджетов собраны, что можно заменить.

## C. Состояния

Для каждой интерактивной части — полный набор, каждый с видом (по темам):

- default · hover · focus / focus-visible · active / pressed · selected / checked ·
  indeterminate · disabled · readonly · required · error / invalid · loading ·
  empty · placeholder / ghost.
- Особые/промежуточные: начало/середина/конец диапазона, «сегодня», день
  соседнего месяца, переполнение, многоточие, первый/последний, пустая панель.
- Какое состояние чем вызывается; какие исключают друг друга (приоритет
  (например, disabled поверх hover).
- Все, что относится только к части (кнопка в панели, строка меню, ячейка) —
  по частям, не «виджет целиком».

## D. Специфика виджета (как живёт)

- **Открытие**: триггеры (клик / hover / фокус / клавиша / вызов из кода),
  задержки, анимация появления (тайминг, кривая, reduced-motion), положение и
  переворот сторон, зазор от якоря.
- **Внутри**: полная структура панели (шапка / тело / футер), что в каждой зоне,
  как устроена навигация внутри (дрилл, подменю, фильтр, страницы), порядок
  элементов.
- **Закрытие**: способы (Escape / клик вне / выбор / потеря фокуса / программа),
  анимация, что возвращается (фокус, значение, позиция прокрутки), повторный
  триггер при открытой панели.
- **Жизненный цикл значения**: до → во время → подтверждение/отмена → после.
- Взаимодействие с окружением: портал / зоны дока, блокировка прокрутки,
  ограничение размеров, адаптивность, локализация, связь с другими виджетами.

## E. Клавиатура и доступность

- Полный кейстеп-маппинг: каждая клавиша и её действие в каждом состоянии
  (включая «ничего»), зацикливание или его отсутствие, модификаторы.
- Фокус: куда встаёт при открытии, куда возвращается при закрытии, порядок
  табов, фокус-ловушка, скрытые закрывающие кнопки для скринридеров.
- Скринридер: роли, aria-атрибуты, объявление состояний, живые регионы,
  прогресс/проценты, скрытые описания.
- Motion: reduced-motion, `noBootstrap`, выключатели анимаций.

## F. Темы и токены

- Все цвета по ролям для **light / dark** (токен + значение), не «светлее/темнее».
- Вложенность тем; secondary-поверхность — только справочно (не рекомендуется).
- Значения, которые совпадают в темах, помечены явно («одинаково в обеих»).

## G. Адаптивность и граничные случаи

- Узкие/низкие экраны, переполнение длинным контентом, длинные значения/слова,
  локализация (даты, числа, списки слов), скроллбар, клавиатурное управление на
  мобильном поведение тача.
- Пересечения с другими виджетами (вложенность оверлеев, связка с формой,
  конфликты хоткеев).

## H. UNKNOWN и расхождения

- Все, что не подтверждено, — `UNKNOWN` в спеке **и** строка в discrepancies
  (ID, статус, план уточнения). Пустых секций «Не определено» без записей нет.
- Код ↔ Figma: расхождение → discrepancies по шаблону файла; в спеку — поведение
  из кода.

## I. Критерии соответствия

- Чек-лист приёмки в конце спеки переписан так, чтобы каждый пункт проверял
  конкретный факт из A–H (проверяемо по тексту, без кода и Figma).
- Пунктов достаточно, чтобы по ним нельзя было «собрать иначе».

## Форма сдачи сессии

1. Обновлённый `design-system/components/<имя>.md`.
2. Записи в `_work/design-system/discrepancies.md` (новые ID, статусы).
3. Отчёт сессии: закрытые пункты чек-листа (A–I) + список оставшихся UNKNOWN.
4. Коммит на ветке; версию не поднимать.
