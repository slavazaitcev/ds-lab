# План: детализация компонентов `design-system/` до 100 % UI/UX-покрытия

Статус: согласован 2026-10-15. Рабочий материал — не нормативный, каталоги
`design-system/` и `design-rules/` не трогает до начала исполнения.

Сопутствующие файлы плана:

- `coverage-checklist.md` — модель «100 % покрытия» виджета (что значит «полно»).
- `component-brief.md` — шаблон брифа сессии по одному компоненту.
- `sequencing.md` — волны, порядок, оценки, известные дыры.
- `tracking.md` — живая таблица прогресса по 30 компонентам + счётчик Figma.

## Цель

Каждый файл `design-system/components/<виджет>.md` доводится до состояния, когда
по тексту **без кода и Figma** воссоздаётся:

- **внешний вид** в любом состоянии (не только «по умолчанию»),
- **поведение** — как виджет открывается, что внутри, как закрывается, что
  происходит с фокусом и значением,
- **все размеры и темы** с точными числами,
- **клавиатура и доступность**,
- **граничные случаи и адаптивность**.

Каждый компонент — **своя сессия** (или несколько для крупных). Сайд-активность:
если при изучении компонента выявлено более точное или новое общее правило —
сессия дополняет `design-system/foundations/` или кросс-виджетные правила, это
легально и приветствуется.

## Решения (согласовано с владельцем)

| Вопрос | Решение |
|---|---|
| Механика | Только план сейчас; диспатч сессий — позже, по команде. |
| Порядок | По зависимостям: примитивы → композиты/выбор → оверлеи → отображение/инфраструктура. |
| Figma | Code-first: максимум из кода autumn-ui; Figma точечно, только где код оставляет дыру (визуальные состояния, точные цвета). |
| Бюджет Figma | Общий ≤ 50 на цикл ревизии (потолок 60), ≤ 8/мин, read-only, без изображений; на сессию ~1–2 вызова; каждый вызов — в `_work/design-system/ledger.md` **до** вызова. |
| Ветка и версия | Вся работа — в **новой ветке** от `develop`. Версия в обоих README + записи в обоих CHANGELOG + журнал по частям — **одним финальным коммитом** в конце программы (не после каждой сессии). |
| Источник истины | Код. Конфликт код ↔ Figma и внутренние расхождения — в `_work/design-system/discrepancies.md` (новые ID, статус `open`). |

## Роли

- **Координатор** (эта сессия): держит план и `sequencing.md`, ведёт счётчик
  Figma-бюджета, принимает сессии по их чек-листам, сводит финал (волна 5:
  версия, CHANGELOG, журнал, финальный коммит), разрешает конфликты правок
  `foundations/`.
- **Сессия компонента**: одна на компонент (для крупных — несколько, каждая со
  своей частью виджета/файла). Работает строго по `component-brief.md`.

## Процесс сессии (обязательные шаги)

1. Прочитать текущую спеку компонента + зависимые спеки (см. `sequencing.md`) +
   релевантные `foundations/`.
2. Изучить код модуля в autumn-ui (прямой доступ к файлам; `ai-grepa`,
   project `autumn-ui`, — для поиска). У каждого факта спеки есть источник.
3. Пройтись по `coverage-checklist.md`, выписать **дельту**: чего нет, что
   `UNKNOWN`, что требует уточнения.
4. Figma — точечно по дельте (лимиты выше). Запись в `ledger.md` до вызова.
5. Обновить спеку: дописать разделы, таблицы метрик, состояния, специфику
   виджета; закрытые `UNKNOWN` → факты; остаток → `discrepancies.md` с планом
   уточнения. Переписать «Критерии соответствия» под новый объём.
6. Сайд-активность: выявленные общие правила — в `foundations/` тем же коммитом.
7. Коммит на рабочей ветке: `<ветка> - <краткое англ. описание>`. Версию **не**
   поднимать.
8. Актуализировать `tracking.md` (обязательно): строка сессии — статус `готово`,
   остаток UNKNOWN, хеш коммита. Актуализация — обязанность сессии, не только
   координатора; без неё сессия не считается сданной.

Приёмка сессии: все пункты `coverage-checklist.md` для виджета закрыты (факт +
источник) либо явно в `discrepancies.md` со статусом и планом. «Молчаливых» дыр
не остаётся.

## Волны (подробно — `sequencing.md`)

- **Волна 0** — подготовка (чек-лист):
  1. Создать ветку от `develop` (имя — ключ тикета, если есть; без тикета —
     осмысленное имя, напр. `detailing-components`; согласовать с владельцем).
  2. Заполнить `tracking.md`: подтвердить оценки, распределить сессии по волнам.
  3. Выдать брифы по `component-brief.md` (по одному на компонент).
  4. Подтвердить остаток Figma-бюджета в `tracking.md` / `ledger.md`.
- **Волна 1** — примитивы и база: text-icon, button, button-group, checkbox,
  input, form, tag, avatar, loader, callout.
- **Волна 2** — выбор и композиты: input-group, selector, input-date-file,
  tag-input, tag-filter, autocomplete, calendar, list.
- **Волна 3** — оверлеи: portal, popover, tooltip, menu, modal, offcanvas,
  notifications, table-pager.
- **Волна 4** — отображение и прочее: lightbox, image-editor, video, bsod.
- **Волна 5** — финал: пройти все «Критерии соответствия» на консистентность,
  свести правки `foundations/`, собрать журнал по частям, поднять версию в обоих
  README, записи в обоих CHANGELOG, финальный коммит. Пуш ветки — по команде;
  MR в `develop` открывает пользователь (в этом репозитории одна ветка `develop`,
  без `master`). Живой статус каждой сессии — `tracking.md`.

Параллельность: сессии одной волны можно гнать группами 2–3, если их правки
`foundations/` не пересекаются; общие файлы (README, discrepancies, ledger)
правит только координатор. Спорные правки `foundations/` — на свод в волне 5.

## Оценка объёма

~30 сессий: 7 лёгких (≈0,5 дня), 18 средних (≈1 день), 5 крупных (≈1,5 дня) —
итого ≈ **30 человеко-дней**. Календарно 4–6 недель при одной сессии в день,
быстрее при параллельных группах.

## Ограничения

- Не менять инвентарь и публичные имена (components/README.md) без запроса.
- `tokens.json` — генерируется (`_work/design-system/build-tokens.py`), руками не
  правится; новые точные значения — через `tokens/` или точечную сверку.
- Не выходить за пределы репозитория; `.opencode/` не трогать (генерируется).
- Не поднимать версию и не писать CHANGELOG до волны 5.
- Не догадываться: нет подтверждения — `UNKNOWN` + запись в `discrepancies.md`.

## Риски

| Риск | Смягчение |
|---|---|
| Бюджет Figma (50) исчерпан до конца программы | Code-first; Figma уходит только самым визуально неопределённым виджетам; остаток — в `discrepancies.md` на следующий цикл. |
| Конфликт правок `foundations/` между сессиями | Волны по зависимостям; общие файлы правит координатор; спорное — на свод в волну 5. |
| `UNKNOWN`, не закрываемый кодом (кривые анимаций, редкие состояния) | Явная запись в `discrepancies.md` со статусом и планом — это тоже «закрытый пункт чек-листа». |
| Разъезд терминологии между сессиями | Единый `coverage-checklist.md`; координатор сверяет формулировки в волне 5. |

## Что не входит в программу

- Новые виджеты, редизайн, «додумывание» отсутствующих состояний.
- Полная визуальная сверка всех виджетов с Figma (отдельный цикл, если понадобится
  после закрытия кодовых дыр).
