Перенеси компонент **$name** из Figma: $link

Ссылка должна вести на набор компонента со всеми вариантами и состояниями. Если это не так или ссылки нет, остановись и попроси нужную. Только чтение: инструменты записи в Figma не используй.

## 1. Подготовка

1. Прочитай `CLAUDE.md` и `docs/token-gaps.md`. Расхождения с Figma, записанные в token-gaps, это решения человека, а не ошибки: не «исправляй» их обратно.
2. Проверь, есть ли `src/components/$name`. Если есть, это обновление: сначала покажи различия между макетом и кодом, не переписывай файл целиком.
3. Образец структуры и стиля: `src/components/Button`. Для составного компонента выпиши, какие готовые компоненты и иконки из `src/components` и `src/icons` ему подходят.

## 2. Чтение макета

Читай один компонент за раз, по вариантам, если выборка большая. Собери:
- варианты, размеры, состояния (default, hover, active, focus, disabled, loading) и какие из них есть в макете;
- размеры, отступы, gap, скругления, обводки, шрифт и размеры шрифта;
- для каждого цвета: какая переменная привязана (фон, текст, иконка, рамка), а не hex;
- иконки: имя, размер, переменная цвета.

Ничего не угадывай. Чего нет в макете, так и записывай: «нет в Figma».

## 3. Таблица и остановка

Покажи человеку таблицу: вариант, состояние, свойство, что в Figma (переменная или значение), что будет в коде. Отдельно перечисли:
1. значения без переменной (числа, цвета вручную);
2. подозрительное: цвет иконки и текста не сочетаются, соседние состояния используют разные переменные без причины, непрозрачный цвет там, где везде прозрачность, белое на светлом;
3. чего нет в макете (размеры, состояния, варианты).

Дождись подтверждения до изменений в файлах. Если пользователя нет на связи, продолжай, но каждое допущение пометь в отчёте.

## 4. Реализация

По правилам `CLAUDE.md`:
- цвета только семантическими токенами `--color-*`; никаких hex, rgb и `--primitive-*`;
- числа без переменной в Figma: добавь в `src/styles/pending-tokens.css` с комментарием «Figma: …» (если значение снято с макета) или «предположение» (если нет); в CSS компонента числа не пиши;
- иконки только через `src/icons/Icon`, цвет иконки токеном `color.icon.*`, задаётся явно; размеры и толщина по `src/icons/spec.ts`;
- файлы: `Name.tsx`, `Name.css`, `Name.stories.tsx`, `index.ts`; классы с префиксом `ds-`; варианты через локальные CSS-переменные, состояния описаны один раз;
- составной компонент использует только готовые компоненты слоем ниже, ничего не рисует заново;
- параметры называй так же, как у существующих (`variant`, `size`, `intent`, `disabled`, `loading`).

Stories: `Playground`, все варианты, все размеры, все состояния рядом (классы `.is-hover`, `.is-active`, `.is-focus`).

## 5. Пробелы

Каждое допущение: комментарий `TODO(token): …` в коде и строка в `docs/token-gaps.md` (дата, где, чего не хватает, что взяли). Если пробел закрыт решением человека, допиши это в той же строке.

## 6. Проверка

1. `npm run typecheck`, затем `npm run build-storybook`. Ошибки исправь, не комментируй.
2. Проверь файлы компонента: нет hex, rgb, hsl, `--primitive-*`; все `var(--…)` существуют.
3. Обе темы (light и dark), все состояния, видимый фокус.
4. Если можешь открыть Storybook, сравни его со скриншотом макета.

## 7. Отчёт

Коротко: что сделано; что взято из Figma, а что допущено; что требует решения человека; в какой story смотреть. Допиши запись в `docs/experiment-log.md` по шаблону из файла. Не делай коммит, пока человек не попросил.
